# Move the new generation pipeline into livinit_pipeline

Issue: https://github.com/anthoai97/livi-pipeline/issues/67 (open). Status: ready for implementation.

Legacy paths below are in the `Livinit-ai/livinit_pipeline` checkout at
`../../../codebase/livinit_pipeline/` (branch `trunk`); links resolve on disk. Facts
checked on 2026-10-16.

## Objective

Production rooms are generated by the new pipeline, through the same service
(`pipeline.livinit.ai`), events and saving flow the web app uses today. The legacy
fresh-generation code is deleted. This repo is archived.

## Current behavior

Production path. `web-pipeline` proxies `POST /api/pipeline` to `livinit_pipeline`
`POST /pipeline` ([router_pipeline.py](../../../codebase/livinit_pipeline/src/api/router_pipeline.py)),
which wraps the body in a `ChatRequest`, resolves auth, the SplitSplat import and
the route, and for `NEW_DESIGN` calls `pipeline_stream_generator`
([pipeline_stream.py](../../../codebase/livinit_pipeline/src/api/execution/pipeline_stream.py)).
That generator creates the run dir, the owned geometry room (`create_geometry_room`,
needed for a UUID `room_id`), runs the shared prefix (`extract_room`, `rag_scope_assets`),
forks three variant states and runs each tail (`select_asset_intent` ... `render_scene`,
2 to 5 minutes), then `_finalize_and_complete`: one response-synthesis model call and the
`complete` event with a frozen key order, `variants` and `turn_payload`.

Web contract ([variantsReady.ts](../../../codebase/web-pipeline/lib/pipeline/variantsReady.ts)).
Each `variant_ready` carries `{data: {variant}}` with `committed: false` and
`create_payload` whose `initial_state` must validate as a `StudioDesignDocument`
([design_v2_contracts.py](../../../codebase/livinit_pipeline/src/api/design_v2_contracts.py)).
On selection the chooser posts `create_payload` to the backend and `turn_payload` as the
first chat turn. The wizard maps legacy node names to its four steps
([nodeStepMap.ts](../../../codebase/web-pipeline/lib/wizard/nodeStepMap.ts)); the live 3D
view reads `asset_update` and `scene_snapshot` for variant 0.

New pipeline ([pipeline/app](../../pipeline/app)). LangGraph graph: interpret, room,
retrieve, rank, then three parallel select, place, finish. Events already use the legacy
node names and the `variant_ready`, `variant_failed`, `complete`, `error` shapes
([contracts.py](../../pipeline/app/contracts.py)) but carry no `create_payload`,
`response` or `turn_payload`, and the service has no auth, room creation or run dir.
It reads `pipeline.pipeline_assets_v2` and `pipeline.asset_embeddings_v2` with psycopg 3.
Both tables exist in the production Supabase database (5,095 products, 5,084 embeddings,
every model URL on the production S3 bucket), with the same counts as the local copy.
Speed: first design 21.5 s median, all three 28.8 s ([report](../pipeline/report-2026-10-11.md)).

## Scope

In scope: copy the generation runtime, rules and catalog search into `livinit_pipeline`;
replace the fresh-generation execution behind `POST /pipeline` and the `NEW_DESIGN` chat
route; delete the legacy nodes only fresh generation used; move tests, benchmark and review
scripts, product-data scripts and the living docs; archive this repo.

Non-goals:

- Edit routes (`MOVE_ASSET`, `CHANGE_ASSET`, `ADD_ASSET`, `REMOVE_ASSET`, `LAYOUT_OPTIONS`,
  `APPLY_LAYOUT_OPTION`, `APPLY_DESIGN_VARIANT`, `USER_FEEDBACK`, `NAVIGATE`) keep their
  nodes and `src/core` rules.
- Furniture found in a room scan (owned assets) is not placed; the new pipeline has no
  fixed-item support (user decision 2026-10-16).
- No change to `web-pipeline` here. The generate and chooser screens are redesigned in
  [#68](68-web-generate-chooser-ux.md), which reads the `node_complete.data` facts this
  plan keeps (see the contracts table).
- Unifying the two rule copies (`src/core/layout` for edits, `src/generation/rules` for
  generation) is a follow-up.

## Decisions

1. Copy and replace, not a second service. One deployment keeps auth, billing pass-through,
   tracing, persistence and the web's base URL unchanged.
2. The seam is `pipeline_stream_generator`. Everything before it (request models, auth,
   route classification, room creation, run dir, trace) and after it
   (`_finalize_and_complete`, `complete`, telemetry) stays.
3. `create_payload` comes from the legacy `_variant_payload`, fed an adapter state dict per
   ready variant. The strict document contract and the mapper stay the single source.
4. New designs no longer raise `fit_confirmation_required`. The room stage already sizes
   the plan (compact and capped selection). `/fit-confirmation/continue` serves edit routes
   only.
5. Scanned rooms keep their shell: `room_model` passes through to the geometry and the
   manifest. Owned assets are ignored.
6. Without a V2 room (unauthenticated benchmark or local run) a ready variant is still
   delivered, with `create_payload: null`, instead of `variant_failed`. Production runs are
   always authenticated, and the benchmark needs ready variants.
7. Live view: variant 0 emits `asset_update` after select and `scene_snapshot` after place
   (`layout_key: "initial_layout"`) and finish (`"final"`). Otherwise the generate screen
   shows an empty room for 20 s.
8. Response synthesis and `turn_payload` stay: Studio's first chat message depends on them.
   The call runs after the last variant, so it delays nothing the user sees.
9. Catalog connection: the service's `CONNECTION_STRING` (Supabase) with psycopg 3 and
   `prepare_threshold=None`, because the transaction pooler rejects prepared statements.
10. Package `src/generation/` keeps our module names (`graph`, `run`, `contracts`, `llm`,
    `jev`, `preview`, `shared_stages`, `variant_stages`, `rules/`) so the moved docs stay
    valid. Catalog access becomes `src/generation/catalog/`.
11. Our `/runs/{id}/previews` and `/runs/{id}/client-timing` endpoints are dropped. The
    production web uses neither. Variant PNGs go to the legacy preview path.
12. The run record is written to `runs/<run_dir>/meta/run_record.json`; benchmark and
    review scripts read it there.
13. Legacy run artifacts the stream wrapper still writes: `run_meta.json`, `trace.json`,
    `final_state.json`, `backend_pipeline_failure.json`, `selected_assets.json`.
14. This repo is archived with its contents kept as reference and a closing note at the top
    of the README (user decision 2026-10-16).

## Phases

### Phase 1: Copy the runtime into livinit_pipeline

- Copy `pipeline/app/*.py` except `main.py`, and `pipeline/app/rules/`, to
  `src/generation/`; rewrite `from app.` imports to `from src.generation.`.
- Copy the runtime parts of product-data into `src/generation/catalog/`: `search_assets.py`
  as `search.py`; `embed`, `MODEL` and `gemini_client` from `embed_assets.py` as
  `embedding.py`; `gemini_usage.py` as `usage.py`; the `Color`, `Material`, `Style` enums
  from `prepare_assets.py` as `attributes.py`. Remove the `sys.path` insertion in
  `pipeline/app/__init__.py` from the copy.
- Settings in `src/config.py`: `JEV_API_KEY`, `JEV_MODEL`, `JEV_USES`, `PRODUCT_REUSE_RATE`,
  `LLM_DESIGN_MODEL` (already read), `LLM_STAGE_MODELS`, `MODEL_HEDGE_AFTER_S`,
  `AI_PROXY_BASE_URL`, `AI_PROXY_API_KEY`. `llm.py`, `jev.py` and the stream read them from
  `settings` instead of `os.environ`.
- `requirements.txt`: add `langgraph>=1.2`, `typesafe-sdk>=0.7.3`, `psycopg[binary]>=3.3`,
  `pgvector>=0.5`, `anyio>=4.14`; raise `google-genai` to `>=2.12`. Our `numpy>=2.5` pin is
  not carried over: the copied code never imports numpy (shapely brings it), and numpy 2.5
  needs Python 3.12 while the image stays on 3.11. Every added package supports 3.10+
  and the copied code uses no 3.12 syntax (checked).

### Phase 2: Replace the fresh-generation execution

Rewrite the body of `pipeline_stream_generator` after the `start` event:

1. Build a `generation.contracts.PipelineRequest` from the resolved geometry (`room_area`,
   `room_vertices`, `wall_height`, `room_doors`, `room_windows`, `wall_finishes`,
   `room_type`, `budget`, `user_intent`). A real USDZ room still runs `extract_room_node`
   first, as today, and its geometry feeds the request.
2. Create the `RunContext` (model client, Jev client, switches, psycopg connection) and run
   `build_graph().astream(..., stream_mode="custom", subgraphs=True)` with the heartbeat,
   run deadline and client-cancel handling moved from `pipeline/app/main.py::_stream_run`.
3. Forward graph events as legacy frames with `_send_event`. `node_complete` keeps our
   `data` and adds `result: {}`.
4. On `variant_ready`: the adapter (`src/generation/adapter.py`) builds the legacy variant
   state (table below), writes `render_scene/selected_assets.json` and the preview PNG to
   `runs/<run_dir>/variant_<i>/layout_preview/layout_preview.png` (the legacy per-variant
   stage prefix; response synthesis opens `layout_preview_path` as an image), then
   `_variant_payload(...)` builds `create_payload`. A mapper or contract error marks
   the variant failed (`variant_failed`, reason `create_payload_invalid`) and is noted in
   the run record. Without a UUID `room_id`, `create_payload` is `null` (decision 6).
5. Variant 0 live events (decision 7) come from the same adapter.
6. After the graph ends: `_finalize_and_complete(mode="full_pipeline", ...)` with the
   first ready variant's state as primary and all ready states as `variant_states`.
   Our run record is written to `meta/run_record.json` in every outcome.
7. Failures: a stage exception before any variant, or a run with no ready variant, goes
   through `_emit_failure` (artifact, `pipeline.run_failed` telemetry, `error` frame).

Adapter state, one dict per ready variant:

| Legacy state key | Source |
| --- | --- |
| `run_dir`, `variant_index`, `room_id`, `workspace_id`, `design_id` (None), `revision` (None), `trace_id` | stream wrapper |
| `user_intent`, `budget`, `room_type`, `studio_state` (`{room_type}` plus request `studio_state`), `wall_finishes` | request |
| `room_geometry` and its keys (`room_area`, `room_vertices`, `room_doors`, `room_windows`, `wall_height`, `room_model`) | resolved geometry |
| `selected_assets` | `contracts.selected_asset` plus `available_colors` (colors), `company_name` (brand), `style` (first style), `product_url`, `description`, `currency`; catalog Decimals as float (the document check runs `json.dumps` on the raw dict, and SSE frames would stringify them) |
| `render_manifest` | `contracts.render_manifest` with `glb_url`, `image_url`, `topdown_url` through `object_storage.access_url`, and `room_model` when present |
| `initial_layout` | the manifest layout (poses with `on_top_of`) |
| `total_cost`, `selection_validation`, `asset_selection_failed` (False), `constraint_events` ([]), `layout_preview_path` | variant result and PNG path |

## Acceptance criteria

1. On the dev stack, generating a room from `web.dev.livinit.ai` shows the four wizard
   steps, three designs, and selecting one opens Studio with the saved design and the
   first chat message. Scanned-room and rectangle-room briefs both complete.
2. `complete` keeps the frozen key order and carries `variants` and `turn_payload`.
3. Studio edits on a design generated by the new path succeed (move, change, add, remove,
   layout options).
4. The quick benchmark set against the dev service delivers all designs with first-design
   and all-three times within the 2026-10-11 report's p90 (32 s, 42 s).
5. The deleted modules are gone and `python -m pytest src/test` passes, including the
   moved generation tests and the `create_payload` contract test.
6. This repo shows the closing note and is archived.

Verification: criteria 1 to 3 by hand on dev; 4 with `scripts/generation/benchmark.py
--set quick`; 5 with pytest; the legacy contract scripts
`src/test/run_v2_commit_contract_cases.py` and `run_chat_tail_contract_cases.py` still
pass.

## Dependencies, rollout, risks

- Secrets: `JEV_API_KEY` in the deploy `ENV_FILE` before the dev deploy.
- Supabase transaction pooler: psycopg 3 must disable prepared statements, or the
  connection string must use the session pooler port.
- Strict document contract: `model_ref` must be non-empty (retrieval already excludes
  products without a model URL), and the raw document must be JSON-serializable, so the
  adapter converts the catalog's Decimal sizes and prices to floats first. The S3 URLs
  become `s3://` references through `S3_BUCKET`, which the service already sets.
- Response synthesis raises when the assistant text comes back empty (legacy behavior,
  unchanged); the run then ends with `error` after the variants were delivered.
- Two rule copies: a layout that passes generation can be flagged by an edit route's
  `src/core/layout` checks. Known drift; follow-up unification.
- Product change: no fit-confirmation dialog on new designs; three live snapshots instead
  of a streamed repair.
- Debug endpoints `/nodes/layout_initial` and `/nodes/layout_refine` disappear.
