the same catalog gap as before. 16 of 17 text query cases pass. Pytest fails
only Q2.

Changes since the earlier report today:

- Text query cases now search the way the slot planner does, with the query's
  categories as a filter, and check how named attributes rank within them. Searching
  without a category is not a pipeline call, so the earlier Q2, Q9, and Q10
  failures tested a search the pipeline never makes.
- Product preparation now keeps one catalog row per product URL. 145 rows that
  repeated another row's product page are gone, so the catalog has 5,084
  embedded products, down from 5,228. Q17 now finds no repeated product page in
  the results or the catalog.

Failures:

- L1, requested sofa: unchanged. Only 3 cream boucle sofas cost USD 1,500 or
  less, and search returns all 3.
- Q2, "black leather sofa" within sofas: the catalog has 8 black leather sofas,
  and the top 10 has 6 of them. Brown and charcoal leather sofas rank 6th, 7th,
  8th, and 10th, so "leather sofa" outweighs "black" in the ranking. The
  pipeline sends a named color as an exact filter, as L1 does with cream, so
  slot search is not affected. Closing this needs a ranking change in the
  embedding text, not a search code fix.

All 13 slots searched at once take 82 ms of database time (69 ms in the
earlier run today), well under the 500 ms limit. One at a time, the median is
4 ms per slot, from 2 to 19 ms. Embedding the 13 slot texts took 0.85 s, with a
median of 0.72 s per text.

## Slot search

These cases run one search per product slot, the way the room pipeline searches, for one living-room request: "a cozy cream boucle sofa under USD 1,500, no rug", with a total budget of USD 4,000.

The tests use the runtime planner's 13 slots and filters for this request. There is no rug slot, because the user excluded rugs. Each slot searches its own text with these filters: its categories, requested attributes, a price no higher than the item's limit and the USD 4,400 allowance (110% of the budget), placeable (3D model, placement, and all dimensions), and a known price. Each fetches up to 30 products. Target pools are 10 for requested and required slots, 6 for optional slots, and 4 for decor.

Pytest verifies that search returns and keeps the available eligible products. This report also checks the target pool size. A correct search can therefore pass pytest while this report flags a catalog coverage gap.

The checks after the search that need room geometry, such as fitting the floor and minimum sizes, belong to the pipeline and are not part of this test.
